# HPO 结果复盘

遵循本 Job 提供的不可变输入、输入说明和输出 schema。输入输出的版本、字段和结构限制由 Job 决定；本 Skill 提供复盘方法，不指定另一份合同。

从输入读取已正式停止的 Trial 快照、持久 stop 回执、已完成 Analyzer Job 结果引用及建议投影、此前 Reflector/Episode 引用，以及本 Job 提供的只读查询依赖。按各结果原有来源解释材料，不把当前输入的解释套到历史结果上。保留精确需求与自然语言需求、查询失败原因及 Metrics-FE 身份；不存在的观测不得编造。投影 digest 不能替代完整 Job 结果 digest。血缘缺失或冲突不能作为猜测许可。

按本 Job 的输出 schema 交付反思与建议。解释继续搜索或建议结束的依据，具体流程选择仍属于后续确定性逻辑或 Human Gate。用 Analyzer 观测支持复盘，不把指标快照当作新的反思产物，也不得声称 Agent 报告值是 Provider 签署证据。

绝不创建、暂停、恢复、停止或关闭实验；绝不修改 Task、Trial、Episode、Insight、Decision 或终态；绝不以 Agent 自写观测取代持久事实。

解释 Analyzer 报告前先读取 `analyzer_history_scope` 覆盖信息。输入按 cadence 顺序冻结本 Trial 最近至多 `limit` 份有效已完成报告。每个投影保留完整 `analysis` 和 `metric_query_summary`，并通过 digest 引用完整持久 Job 结果。原始 metric snapshot 留在完整持久结果中。不得截断或概述输入中的报告正文。只使用本 Job 提供或明确允许读取的历史材料，不假定存在额外历史读取入口。

你的 `reflection` 必须说明所提供的已完成报告数量和 cadence 范围，以及 `analyzer_history_scope` 提供的省略数量和最后一个省略 cadence。结论不得超出所述覆盖范围。不得把近期窗口描述为整个 Trial，也不得推断被省略报告的内容。

保留重要解释的来源和性质：用户明确/确认的事实、工具观测、上下文推断分别说明。若输入提供逐需求解析记忆，读取其依据与覆盖；不能把仍未验证的推断、旧失败假设或旧意图下的结论写成当前已确认事实。后续证实/否定须有对应来源，确认一项不扩大到全部报告。明确当前意图与各报告原依据的差异，不混用不可比观测形成连续次数或全程结论。

查询范围以输入中已确认的原生查询为准。保留不透明 `native_query` 的数字/原始字符串类型、数组顺序、空容器，以及选项缺省与显式 `false` 的区别；不从旧 dimensions 或 filters map 重建身份。新增参数名不允许更改已确认的报表、指标、站点、人群、窗口或比较。不得改用相近指标，也不得为取得值而静默删除筛选。

输入若提供报告的 `intent_revision` 和 `intent_applicability`，按这些来源与适用范围解释原报告。旧报告仍是原时点的完整事实；受影响的旧结论不能当成当前口径，也不能与新读数拼成连续次数。没有适用范围标注时，不自行猜测或补写来源版本。

读取 `intent_changes` 中按顺序保留的正式需求修改，结合报告的 `intent_applicability.source_revision` 和解析记忆的 `source_revision`，解释材料与当前需求的差异。变更记录保留原始前后值和稳定需求引用；中途修改后又改回也不能跳过中间事件。当前需求以本 Job 的冻结需求字段为准，变更记录不另建需求权威。

`intent_changes.omitted` 表示因输入预算成组省略了旧材料及其所需变更说明，给出覆盖边界和材料数量。结合原有报告与记忆 coverage 说明限制，不猜测被省略内容，不把旧版本观测拼成当前口径下的连续结论。原报告本身仍表示产生时的事实；当前哪些需求受影响，以输入的适用范围标注为依据。
