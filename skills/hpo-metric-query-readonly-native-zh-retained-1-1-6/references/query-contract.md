# Analyzer 查询合同

当前 Job 持久化的 Task context 是唯一 Task 需求输入。它的观测 context 提供当前实验、baseline 和 treatments；结果如何表示由主 Skill 锁定的输出 schema 决定。

发现、查询语义与诊断请读[共用指南](metric-query/GUIDE.md)。把需求、解析身份、实际观测方式和结果分开。最初未解析的需求可在运行时解析；一次尝试采用新方法不会改写冻结 Task 需求。

对于尚未解析的线索，沿其来源追查 namespace 提示。数据新鲜度或 Agent 先前推断不会绑定查询面；应重新检查原始业务路径和实际定义。保留精确用户身份与约束。区分新查询与带有时间和范围的历史证据，并在既有分析字段记录发现方式的变化。仅有元数据的发现、不完整预览，或对其他需求成功的查询，都不能解析本需求的身份或值。

对精确 `hpo.libra-native-metric-query/v1` 身份，按[Libra 知识](metric-query/libra.md)使用冻结的 `native_query` 对象。其原生子命令、原始参数和响应行选择规则是已确认数据，不是 HPO 的类型化参数映射。执行时才替换当前 Trial flight、当前组的版本/名称/配置，以及当前观测窗口占位符。`query_method` 记录完整实际命令，但返回的原始冻结身份保留占位符。检查返回组属于本 Trial。不得重用参考 flight/版本 ID 或组标签、移除筛选、遗漏必需日期，或为取得数值改变人群。新的 Provider flag 属于数据，不是新 HPO schema 字段。

旧广告报告 argv builder 是旧类型化形状的可选辅助工具，不是新的身份合同，也不提供查询窗口。需要时阅读当前官方命令帮助和实际响应定义。query namespace 用于选择知识；不得把业务上的 realtime 新鲜度词解释成实时看板 namespace。Metrics-FE 保留其既有身份、当前组标签占位符及原始 URL。

在既有分析字段描述已尝试请求、观测时间、经过清理的结果/错误和剩余不确定性。执行回执保留在普通 Runtime trace。身份证据和值是否可用是两件事：真实且无法区分的候选为 `ambiguous`；发现/查询失败为 `error`；准确定位指标且成功取得完整响应、但没有可用值时为 `missing`。成功元数据查询返回零匹配，只说明已查范围内没有匹配；身份仍未解析，不是歧义，也不是值查询前的观测缺失。以上任何状态都不是零值、成功、guardrail 通过或停止实验的许可。
