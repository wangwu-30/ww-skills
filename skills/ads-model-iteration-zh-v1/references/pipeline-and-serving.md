# 流水线与在线服务

当问题涉及特征系统、训练数据、数据流、在线服务或上线链路时，读取本文件。

## 端到端概览

标准广告模型工作流可分为四步：

1. 特征工程；
2. 模型开发与训练；
3. 在线服务与上线；
4. AB 验证。

也可以分为两个层面：

- 算法层：目标定义、样本构造、特征设计、模型结构；
- 工程层：数据流、特征服务、在线预测、上线与回滚。

## 训练数据基础

### Slot / FID / Instance

传统稀疏特征栈围绕几个关键术语组织：

- `slot`：特征组或类别，例如 uid、aid、creative_id、query；
- `FID`：最终编码成整数的稀疏特征 ID，概念上可理解为 `slot + hashed value`；
- `instance`：一个训练样本，可能包含特征、标签、样本权重、行 ID 和相关字段。

这套系统旨在把维度极高的稀疏广告特征转换为统一的、可训练且可服务的表示。

### Feature Column / Feature Store

随着广告特征系统发展，表示方式已超出早期按行组织的稀疏样本：

- `Feature Column`：更广泛的特征表示，可表达稀疏、稠密和序列类特征；
- `Feature Store`：管理训练样本和特征数据的新方式，组织更偏列式，也更容易支持训练和回溯。

因此，广告模型的数据组织不再只是“拼接一行日志再训练”。

## 特征来源

广告模型特征通常来自三个方向：

- 广告侧：广告 ID、创意、广告属性、商品属性；
- 用户侧：用户 ID、长期行为、短期行为、兴趣；
- 上下文侧：流量、位置、设备、时间、环境。

一个关键工程原则是：

- 尽可能复用训练和在线服务中的特征提取逻辑。

## 特征提取方式的演进

### Seraph provider

- 早期的函数式特征提取；
- 易于起步，但复用和维护性较弱。

### BFS

- 基于 DAG 的特征计算框架；
- 抽象公共特征逻辑；
- 曾长期作为主要特征工程框架。

### Academy

- 更新的平台化特征开发框架；
- 目标是统一数据源、离线逻辑和在线特征表达；
- 减少重复开发及线上线下不一致的风险。

### 实际理解

- 早期：手工且分散的特征逻辑；
- 中期：以 DAG 为核心的特征工程；
- 后期：平台化、服务化的特征系统。

## 数据流为何重要

许多广告目标依赖近实时的样本拼接和标签回流时机。

这对 CTR、CVR 和转化相关任务尤其重要，因为：

- 正样本可能延迟到达；
- 负样本可能先出现；
- 不同广告和目标的延迟不同。

这会直接影响：

- 样本如何拼接；
- 模型训练时能看到哪些标签；
- 预测结果的稳定程度。

### Fast emit

`fast emit` 是一项核心数据流思路：

- 尽早发送正样本；
- 必要时延迟发送负样本；
- 减少正负样本到达时间不一致的问题。

这样做是为了减少延迟反馈造成的分布失真。

如果用户询问模型为何突然高估、低估、超支或流量下降，应先检查 `fast emit` 和负样本时机，再判断网络是否有问题。

## 在线服务链路

### Marine

- 通用在线预测服务；
- 将在线特征转换为模型输入并调用推理执行。

### Viking

- 与召回和粗排更相关；
- 处理向量检索、ANN 检索和相关在线排序路径。

### Pilot

- 在线执行模型计算图；
- 充当推理运行时。

### Online PS

- 存储稀疏 embedding 和相关模型参数。

## “在线服务”的实际含义

模型不是一个只需执行的静态文件。

完整链路是：

1. 特征生成；
2. 特征查找；
3. 计算图执行；
4. 返回结果并接入后续链路。

## 上线与实验注意事项

### 粗排上线方式

历史上存在不同的上线方式，例如：

- 较早的 `cypher_ad_reload`；
- 较新的 `feynman_ad`。

较新的方式通常更接近统一的训练与特征服务，也可以更快更新广告向量。

### 精排上线

- 通过 Pilot 和 Marine 走较新的模型服务路径。

### 解读实验时的注意事项

查看线上实验时，关注：

- `AA` 效应；
- 预算桶造成的伪影。

未经检查流量拆分、预算行为和广告分布影响，不要默认相信实验读数。
