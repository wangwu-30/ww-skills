# HPO 结果分析

遵循本 Job 提供的不可变输入、输入说明和输出 schema。输入输出的版本、字段和结构限制由 Job 决定；本 Skill 提供分析方法，不指定另一份合同。

从输入读取 Task、Trial、Binding、组快照、cadence 和指标查询锚点。使用本 Job 已安装的 `queryMetric` 与 `bytedcli` Skills 执行只读查询。已确认目标与 guardrail 是完整的需求权威。精确身份可使用 Libra 或 Metrics-FE；自然语言需求可能需要解释。保留用户约束、区域、站点、人群和成功策略。查询 Provider 不会改变实验 Provider，也不授权生命周期写入。

按本 Job 输出 schema 交付分析、查询结果及建议。保留当前 Task、Trial、绑定和组的来源，准确记录观测时间及其时区，不把自己的报告写成 Provider 签署证据。

读取每项冻结需求原始的分析、成功和 guardrail 条件、先前观测时间和读数，判断当前哪些需求到期。以需求引用区分本轮检查对象；未到期而未检查与已检查但查询失败是两回事。即使查询相同指标，两项需求也可能有不同的条件和适用范围，不合并解释。

- 保留已确认的精确身份，或说明本次如何解析自然语言需求。一次解释不会改变冻结 Task 需求。
- 记录实际只读查询方法、已知观测窗口及适用的当前实验组。窗口未知时如实说明。按冻结需求的适用范围查询；仅针对实验组的需求，不把对照组缺口纳入该项判断。不得替换为参考实验组或版本 ID。
- 区分观测值、值来源与统计依据。零是有效值，缺少读数不能补零。
- 分清身份尚未解析、真实候选存在歧义、发现或查询失败，以及成功查询后没有可用值。保留具体原因和已尝试方法；不能完成查询时，不隐去这项已检查需求。具体状态与结果表示遵循本 Job 的说明和 schema。

整体查询说明应概括本轮检查范围及各项缺口。即使部分观测已支持停止建议，也要保留其他已检查需求的缺失、歧义或失败事实。

提出停止建议时，用本轮已观测且符合适用组范围的证据解释原因，说明其他需求的缺口及本轮未查项。按本 Job 的输出说明关联支持建议的需求，旧读数单独不能冒充本轮证据。平台负责后续人工决策和流程，该建议本身不会停止实验；Agent 报告不会自动授予控制权限。

本 Job 允许建议下次检查时间时，根据下一项到期需求、条件、历史和数据新鲜度作出建议。遵循输入说明中的调度含义和等待范围，不臆造默认值。分析耗时影响实际观测间隔；等待上限不等于每项需求都能在该时间内取得观测。

缺口若依赖用户独知事实，按本 Job 的交互说明提出具体业务问题，例如哪份报告或站点代表目标路径，或零流量是否符合预期。缺失日期参数、工具或传输错误及可从已安装 Skills 查明的事实属于你的诊断职责：修复或报告实际失败。完成当前报告后继续监控，等待用户答复。若有 `open_question`，在分析中说明仍在等待，不重复提问。

后续 `question_answers` 只能作为解释材料，并保留用户原始答复。选择范围覆盖整个 Task，包括更早 Trial。读取 `question_answers_coverage`：`latest_request_ref_by_requirement` 把每项需求映射到最新已回答请求。多个需求共用的问题只携带一次原始引用；仅应用于当前映射仍指向该请求的需求。更新答复会替换该需求的旧答复。`included_request_refs` 和 `omitted_request_refs` 标明预算中携带或省略了哪些完整答复。省略的答复不是撤销事实，也不能据此采用过时答复。解析记忆也有独立 coverage；不得假定其中包含已省略原始答复的方法或身份。答复完整保存在决策历史中，当前输入的范围以其覆盖说明为准。答复不会改变冻结需求或精确身份。若答复要求不同的已确认身份或含义，仍是缺口；用户须走原有流程修改需求。

把经过清理的查询回执留在 Runtime trace。不得把原始工具输出、凭据、trace 文本或未声明字段放进有界结果。不得写入 Task、Provider、实验或证据。

解释提供的 Analyzer 报告前，先读取 `history_scope` 覆盖范围。输入按 cadence 顺序冻结了本 Trial 最近至多 `limit` 份有效已完成报告。每份投影保留完整 `analysis` 与 `metric_query_summary`，并通过 digest 引用完整持久 Job 结果。每份报告的 `requirement_resolutions` 可包含已采纳查询状态、原因、解析身份、执行方式、观测时间/窗口及分组读数/统计。`latest_requirement_resolutions` 独立提供每项需求最近一次已检查报告的解析，它可能早于当前完整正文窗口。优先复用此前成功的解析方式，同时替换为当前 Trial/组/窗口值；若证据变化或先前失败，则重新发现并解释新方法。旧解析是有用证据，但不是新的冻结身份。需要连续观测或累计条件时，使用实际历史读数；不得从摘要虚构连续性。

读取 `resolutions_coverage`：计数器说明方法、组读数或整项记忆因预算省略的范围；完整持久结果不变。缺少读数不等于零。整项省略计数无法指出此前检查了哪些冻结需求，不得据此推断缺失记忆等于从未检查。不得截断或概述输入中的报告正文。更早报告以完整正文形式省略，其最近需求事实仍可能出现在独立记忆中。只使用本 Job 提供或明确允许读取的历史材料，不假定存在额外历史读取入口。

问题/答复记录仍保存在既有持久人工决策历史中。累计问题历史过长时，输入 coverage 是独立的有界交接决策；不得声称当前输入包含所有先前答复。

使用 `history_scope` 区分近期证据和 Trial 全部执行历史。不得推断被省略报告的内容，也不得把近期模式说成覆盖全部历史周期的结论。

对已确认 Libra 身份，使用本 Job 冻结的身份与原生查询字节作为查询依据。不要把旧 dimensions/filters map 重建为身份，也不要调用其 argv helper 作为身份合同。命令参数查已安装 bytedcli Skill 的最新帮助；对该指标使用冻结的原生子命令和参数。执行时才把 `{{trial.flight_id}}` 替换成当前 Trial；并分别解析每个当前组的 `{{group.version_id}}`、`{{group.version_name}}` 和任意 `{{group.config.<candidate path>}}`。`{{window.start_date}}`、`{{window.end_date}}`、`{{window.start}}`、`{{window.end}}` 从观测窗口解析。不得复制参考 flight、日期或版本值到新 Trial 查询。例如固定筛选 `abtest_bingo=1` 应保持原始字符串筛选值 `"1"`，既不是数值维度，也不是版本 ID 替换。

使用冻结查询的行选择规则和完整响应元数据，选出目标指标、当前组行及所需比较键。不得把第一行当捷径。正常读取检查受支持的参数、本方调用、内外层状态和响应完整性；调用正确且结果匹配时可以采用，缺少 SQL/scope 本身不是拒绝理由。已有证据表明筛选被忽略、对象错误或响应截断时仍不得采用。新方法接入、参数语义改变或具体矛盾时才做针对性验证，不要求每轮额外取 SQL、做差分探针或审计完整 HTTP。`query_method` 记录完整实际命令，包括替换后的 Trial/组/窗口值。原生 report-link、表名、指标名与 ID 选择器可能因 Provider capability 而异；保留冻结选择，不强行统一语法。旧 helper 缺少窗口参数不授权省略实际观测日期。

成功但无值不是零，也不一定是等待数据。结合逐需求记忆和当前元数据，区分数据产出条件未满足、查询路由不匹配和筛选生成条件缺失。实验区域、配置及数据新鲜度各自能排除哪些原因，比重复错误码更有用；Provider 把空数据包装成错误时，也要读其具体含义。诊断方法见共用查询指南及对应 Provider 说明。

诊断报告说明新证据改变了哪个判断：原因已查明时，给出具体错误事实、影响和正式修订建议；仍未知时，保留已排除的假设及最有价值的未决问题。把这些结论也留在对应需求的解析记忆中，让下轮能接着调查。没有新依据、修复或条件变化时复用已有诊断，正常数据刷新按原节奏继续；等待应对应实际产出或观察条件。

把用户明确/确认的事实、工具直接观测与上下文推断分开。重要推断须在需求解释及解析记忆中保留依据、出处和未验证性质，不仅写在可能退出近期窗口的分析正文里。后续证实或否定要给出新依据；重复引用、报告接收或确认另一项都不能把推断变成已确认事实。正式修改当前 Task 意图与普通问答分开，旧 Job 和历史继续表示原依据。

读取 `intent_changes` 中按顺序保留的正式需求修改，结合报告的 `intent_applicability.source_revision` 和解析记忆的 `source_revision`，解释材料与当前需求的差异。变更记录保留原始前后值和稳定需求引用；中途修改后又改回也不能跳过中间事件。当前需求以本 Job 的冻结需求字段为准，变更记录不另建需求权威。

`intent_changes.omitted` 表示因输入预算成组省略了旧材料及其所需变更说明，给出覆盖边界和材料数量。结合原有报告与记忆 coverage 说明限制，不猜测被省略内容，不把旧版本观测拼成当前口径下的连续结论。原报告本身仍表示产生时的事实；当前哪些需求受影响，以输入的适用范围标注为依据。
