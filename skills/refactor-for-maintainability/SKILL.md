# 可维护性重构

让修改一项业务规则、存储决定或执行协议时，只需理解直接相关的少数模块。需要实际消除的是调用者必须记住的事务顺序、活对象形状、状态清理、全局配置、版本分叉、重复解释和交付约定。文件变短、接口改名、bug清单变长、检查器通过，都不证明这个目标已实现。

本 Skill 提供重构的判断依据、责任地图和完成标准。当前仓库或用户已有方案设计、方案比较或沟通方法时，诊断、候选比较、挑刺消融和最终表达按那些方法进行，不另起一套流程。

涉及跨线程、事务、远端、恢复或制品阶段的操作协议时，读取[跨边界操作协议设计](../boundary-protocol-design/SKILL.md)。该来源承担结果成立条件、实际身份穿过失败路径、资源跨等待、迟到输入和重启收尾的具体设计；这里保留它们在整体结构中的归属，不重复规定操作协议步骤。按链接实际读取，不能因名称出现在上下文里就假定方法已加载。

## 按请求决定分析与完成范围

**整体评审或大重构：** 建立当前生产入口、真实写方和消费者的责任地图，沿完整生命周期展开，再给出能覆盖目标范围的最终结构与删除动作。读[重构责任地图](references/refactoring-map.md)；涉及升级、安装、构建或宿主运行，续读[迁移与交付](references/migration-and-delivery.md)。不能用几个代表链路、发现数上限、一次容易通过的补丁或纯bug审计替代整体目标。分单元实施可以支持整体完成，不改变完成标准。

**局部结构改造：** 从本次动作展开直接相邻的事务、状态、输入和消费者；只读有关参考段。范围由真实耦合决定，既不自动启动全仓治理，也不把跨模块问题截断在当前文件。

**继续长期改造：** 先恢复用户已定目标、最新差异、已完成与剩余义务。旧方案和顾问判断核回当前实现；已获准的一次性目标不能在压缩后退回“实施节奏待定”。局部通过后继续收口剩余责任与组合验收。Skill不增加产品变更、外部操作或消息权限。

## 从修改成本找到知识的主人

沿真实入口说明一项常见修改现在会牵动哪里。例如改结果采用规则、增一种执行器、加一个阶段字段、更新当前发行，调用者还必须懂哪些无关内部？调查直接import之外的协议：参数、副作用、失败顺序、时间条件、全局装配、文件资源、生成物和安装制品。把Session改成Any、返回ORM或复制内部字段的接口仍可能要求调用者掌握完整存储。

地图至少把当前目标相关的以下责任区分开；整体重构须对每项说明适用、已闭合或缺证据，不能只列目录：

| 责任 | 要追的实际输入、动作与结果 |
|---|---|
| 业务用例与纯规则 | 用户动作→所需事实→规则→完整写入→公开结果 |
| 事务与外部效果 | 锁/写/审计/通知的原子范围；意图→外部调用→回执→本地采用 |
| 执行、状态与恢复 | 冻结请求、运行位置、阶段现场、未消费输入、进程资源、持久交付 |
| 接收与业务采用 | 原Job/claim/输出合同准入，和当前业务是否适用的分别判断 |
| 类型、版本与依赖 | 叶子合同、当前选择/已锁执行、解码边界、真实进程/实例装配 |
| 查询、校验与删除 | 事实的写方/变化范围、观察对象、动态授权、机制的真实消费者 |
| 迁移与制品 | 旧起点、升级依赖/事务、导出/安装/激活、系统依赖和历史恢复 |
| 验证与整合 | 实际入口、故障/并发/历史/制品行为；调用方迁移与旧机制退出 |

这些维度帮助发现责任，不要求每个项目建设相应模块。未启用设计、测试虚构未来配置与真实发行义务分开；不能从没有静态调用直接推出没有动态或安装后消费者。

## 给出完整动作，而非接口壳或问题清单

设计围绕会独立变化的知识，同时保住必须一起成立的不变量。用一条具体过程说明最终结构：谁拿事实、谁决定、谁加锁和提交、谁等待、谁恢复、谁关闭资源；列清调用者少记了哪条约定、哪份副本或机制会实际删除。

- **用例可读：** 业务入口处理普通事实和规则，SQL/文件实现承担完整存储动作及其内部细节。业务规则不要搬进巨型Store，端口也不要返回任意内部对象。
- **现场有归属：** 运行进度、当前阶段、未消费输入、冻结业务材料和执行资源按含义/寿命分开。恢复合同由明确业务状态产生，不随实例反射、私有属性或另一份字段清单漂移。阶段应收窄输入和写权；路由权威仍留原流程。
- **接收与采用各有归属：** 公共完成入口与业务采用规则按各自会变化的知识组织；结果含义与采用条件由跨边界操作协议方法推导。接收完整承重后再删消费侧重复部分。
- **版本集中解释：** 当前选择、已锁执行、历史解码各有明确边界；内部拿语义，不到处查版本字符串。共享类型不反向依赖整个注册表，延迟import不能代替消除依赖环。
- **依赖随消费者：** API/Worker/执行器从实际实例取得依赖；共同结果类型不归某个厂商私有模块。资源所有权与生命周期沿实际操作设计，共同执行不需要引入新调度器。

已有函数和能力若能完整承载责任，先改它。新模块的价值来自隐藏知识；新增转发层、万能Repository、多个actor、校验票据或通用恢复框架要解释当前净收益。两段相似代码若共享同一政策可收口；独立业务规则不为去重而合并。

## 减法也是设计产物

对重复扫描、历史自证、摘要、票据、回读、fallback、空预留能力和旧入口，追它究竟捕获什么，以及哪个真实写方/消费者需要它。不要只将机制搬到另一个文件。

稳定同一观察范围内可解释一次、返回小事实，空结果也是可复用结果；写方可能改变事实、释放锁后使用、权限/claim在等待后变化，则仍须相应核验。正常读热路径不承担所有历史完整性重建，历史诊断/修复若需要则有自己的入口。

输入/产物/发行摘要有内容身份用途；普通业务值相等未必需要hash，自摘要不证明独立正确。删除后必须指明原机制的实际保护由谁承担，或证明没有当前义务；不设一律禁hash/禁回读/禁监听器。泛化“执行后所有输入永不改变”也是一种准入政策，可在明确业务目标下改为检查实际产物与归属；这是合同变更，须版本化并覆盖全部生命周期，不能伪装成去重或凭现状永久保留。

按需展开[因果案例](references/decision-cases.md)：事务C01/C09/C10；状态C04/C05/C15；完成C16；读取C06/C08/C12/C17；类型/实例C14；迁移/交付C18–C21；交互C22；验证C02/C03/C07/C23。案例是匿名经验或明确构造，不是当前项目的事实。

## 实施到真实调用和交付

保留已定业务含义、原子关系、锁顺序、错误类别与先后、冻结历史、未知外部效果的恢复权。真的要改变这些合同，显露改变及消费者；不要以“结构调整”偷偷改，也不要把当前约定自动当成永不允许改变的要求。

每个实施单元包含实际主人、调用方、旧出口退出、相关制品和区分性验证。先建立完整承重的新入口，再迁消费者、删重复规则和死协议；不留下“新类＋旧字段＋兼容代理”长期三份同步。测试替换点须落实际调用处；公开或安装后薄入口有真实兼容义务时保留，内部迁移已完成的历史转发应退出。

按跨边界操作协议方法完成准备、等待、采用和收尾的调用方迁移，不能仅迁成功入口。计数在其代表事实成立处更新，采用次数不同于预占预算。

## 用行为证据检验改造，而非证明文本长得正确

先定义能区分新边界与旧缺陷的观察：中途失败后整组记录、并发赢家和输家、旧生产者材料的恢复、真实进程组退出、安装后的公开入口、当前已读取事实与后续新事实。真实升级要从旧起点调用正式升级，构建验证要让必要阶段失败并停止；抄SQL、源码关键词、假进程、只在新实现里生成再回放，不能证明这些对象。

失败先判是否到达目标、材料是否为合法历史/当前合同、替换点是否生效、环境和制品身份是否正确，再判断旧形状束缚、原缺陷或本次回归。保留初失败与复验，必要用未改基线/正确环境对照；不要默认旧测试要改，也不要改产品迁就错误环境。

替换检查可用等价改写应接受、破坏真实行为应拒绝的对照。消融要到达目标路径；互相兜底、协作机制与组合义务不能用各自删除后局部绿推断整体可删。相关方法疑难再读[工程依据](references/engineering-foundations.md)。

整体完成要核最终差异与同一候选：实际业务入口和部署/安装调用方已迁、旧协议及副本已退出、既有行为和新合同有对应证据、迁移/历史/制品/组合验收覆盖其对象。逐项已完成、未完成、未验证分开；测试数量、格式合法或覆盖索引不代替这些事实。

向用户解释最终过程、当前痛点、具体减法、保留保护和证据。整体方案应形成少数有因果关系的责任边界；问题台账作为证据附属，不能用几十个小bug代替架构方案。
