# 因果案例

只读与当前问题相关的案例。C01—C12、C14—C23是匿名化经验，来源包含主改造和邻接交互审查：观察和验证描述来自当时记录，不表示此刻重跑，也不为当前项目设合同。C13是说明性构造。每例保留改变选择的事实及条件；原始来源和评测材料由制作者另存，使用不依赖它们。

| 要展开的知识 | 案例 |
|---|---|
| 操作原子范围及交接 | C01、C09、C10 |
| 状态含义与寿命 | C04、C05、C10 |
| 稳定事实与变化事实 | C08、C12 |
| 冻结恢复、接口与实例装配 | C06、C14 |
| 检查、证据与对外合同 | C02、C03、C07 |
| 决定恢复与外部意见 | C11 |
| 同一知识与相同写法 | C13 |
| 完整状态、接收与查询职责 | C15、C16、C17 |
| 升级、制品与历史资源 | C18、C19、C20 |
| 独立发行算法与原payload恢复 | C21 |
| 简单交互与真实进程验证 | C22、C23 |

## C01 创建函数暗中结束调用者的事务

**情境与假设：** 两个流程都创建工作记录。公共函数自行提交或回滚，看似让调用方省心；一个流程须把工作与关联记录一起保存，只好另写插入代码。

**改变判断的事实：** 对照中，调用者此前写入、尚未提交的事件被公共函数的隐藏回滚丢掉。重复实现是在躲避这个效果。

**选择与原因：** 共用写步骤只写入及必要刷新，由拥有原子范围的操作结束事务。两个流程各自保持“工作＋排队事件”和“工作＋关联记录”的原子范围；隐藏租约回收成为明确步骤，保留其原事务和锁顺序。中途故障后观察整组记录，确认无半组。调用者少一条禁忌，插入规则少一份副本。

**重议条件：** 独立命令、不参与其他写入组合时，入口可自行提交。不能把所有提交推到最外层，也不能为共享插入合并原本独立的租约回收事务。

## C02 临时属性与更新监听器的写协议

**情境与假设：** 修改记录前须设临时属性；监听器回查事件、核修订号，成功依赖几次刷新。它被解释为安全网。

**改变判断的事实：** 数据库已有“修订绑定唯一回执”保护，监听器重复核对；但缺少确认信息的旧记录只受较窄保护。全删会丢旧记录的冻结字段规则。

**选择与原因：** 明确修订操作内部负责事件与记录写顺序，数据库继续承担真实约束；旧记录规则保留在能承担它的边界。调用者不再记临时属性和刷新次数。同源约束没有被自动当成无用自证。

**重议条件：** 出现绕过操作的批处理或运维写方时，重核数据库保护范围。未知时先查，不能凭“重复”删除。

## C03 构建配方与同一提交的自摘要

**情境与假设：** 检查器维护配方摘要、指令解释器和源码关键词，用于证明构建可靠。

**改变判断的事实：** 等价缩进、注释、局部变量改名会误拒；检查器、摘要、配方同属受审提交，同步改写不产生独立信任。关键词出现不说明构建运行必要检查并遇错停止。

**选择与原因：** 用实际构建承担执行要求，分别注入静态检查、组件测试、类型错误，观察是否在对应阶段停止。删除自摘要和脆弱语法识别，保留依赖安装、产物身份及镜像对应核对。配方修改不再同步另一份解释器。

**重议条件：** 摘要来自独立审核或签名方时承担不同义务。同源类型检查、唯一约束、输入验证能捕错，不能套用本例全删。构建实测只支持实际走到的阶段与环境。

## C04 失败写回覆盖较新的计数事实

**情境与假设：** “已采用次数”尝试前保存、失败后写回，希望失败不占次数；等待期间策略更新按规则清零。

**改变判断的事实：** 失败写回把较新的清零覆盖成旧值。

**选择与原因：** 在采用成立时更新次数，审计所需下一值明确传入，去掉保存和回写。复现覆盖成功、拒绝、等待期间清零，说明此流程无需额外代次或回滚框架。

**重议条件：** 预算预占代表执行前必须占用的资源，可先占用再按合同释放。采用时点不决定存储机制：单执行者局部状态与并发持久计数分判，不从“计数”推导数据库事务或原子递增。

## C05 换节点、重试与换轮次的清理边界

**情境与假设：** 多阶段共用状态袋，进入下一节点清理上一节点；后来把逐字段清理搬进对象，认为职责已收敛。

**改变判断的事实：** 重试和人工处理会回到前面，换节点清空丢失有效现场；主循环新一轮已整体替换现场，后续逐字段清理重复。搬清单没消除新增字段须同步清单的义务。

**选择与原因：** 实际新轮次整体建立新现场，重试沿用本轮事实；通过真实主循环观察替换时点，删重复清单。冻结输入、未消费消息、执行句柄按各自寿命区分，不都装进同一恢复对象。

**重议条件：** 跨轮事实显式携带；不同清理时点的资源不能随现场丢弃，替换须核旧引用是否仍被其他执行者使用。

## C06 存储对象改叫端口仍需懂整个内部

**情境与假设：** 退出存储库直接导入后，宽接口用任意类型透传活对象；按角色拆多个接口似乎完成解耦。

**改变判断的事实：** 调用者仍懂存储结构和其他角色规则。读取顺序混合恢复冻结工作与创建新工作。

**选择与原因：** 先查冻结工作，存在就核原绑定并恢复，不读当前模板或要求旧正文文件存在。创建新工作才读当前所需事实，由规则生成输入，原操作派发。公共派发和领取可共享，各角色业务判断不用挤进统一准备函数。

**重议条件：** 恢复对象不含完整输入、只存引用时仍须读取；动态授权另核。多个角色使用同一事实及不变量时，共享读取合理。已发布薄入口有兼容价值，接口薄不是删除证据。

## C07 合并锁和校验改变错误合同

**情境与假设：** 外层锁定校验后解锁，内层再锁校验；合并为一次锁、校验、提交，预期只简化结构。

**改变判断的事实：** 旧草稿误放行，冲突错误变成格式错误，内容与权限校验先后改变。拒绝时机与用户看到的错误属于接口行为。

**选择与原因：** 保留清楚的单操作，恢复已承诺拒绝范围、错误种类、顺序，以对应反例核验。调用者少懂协调，对外含义保持。

**重议条件：** 产品决定改变合同并处理消费者时可调整。无需永久保留重复实现，也不能借“去重”暗改合同。

## C08 登记成功后要求状态仍未前进

**情境与假设：** 登记提交后回读“仍待执行”，下游重复逐字段核对，认为这样证明成功。

**改变判断的事实：** 事务已确定不可变意图，执行端随后正常领取；“仍待执行”把成功进展误报为失败。

**选择与原因：** 登记直接返回锁内稳定身份与意图；接收、恢复处解析材料，执行事务核动态授权。领取后重投登记仍返回同一操作，不要求倒回旧状态。

**重议条件：** 提交后可变部分可重新观察；稳定身份不代表权限永久稳定，不能由本例删除所有回读。

## C09 远端成功与本地失败没有共同回滚

**情境与假设：** 上游发布期间保持本地事务，想合并本地提交获得更强原子性。

**改变判断的事实：** 隔离探针观察 A 远端成功、本地登记失败；B 发布同名不同内容成为本地所有者；A 恢复被归属规则拒绝。本地回滚没撤销远端效果。

**选择与原因：** 明确持久意图、外部调用、结果保存、本地登记的交接及各自原子范围。返回丢失后可否查询或重发取决于原幂等和查询合同。名称何时归属是业务决定，不从拆事务自动推出。

**重议条件：** 确认查询、幂等键或名称预占合同后，按其含义选择恢复。本例支持故障窗口与理由，不声明所有窗口已实施解决；未知时不能猜远端可安全重发。

## C10 协程取消而写线程仍在提交

**情境与假设：** 数据库准备移到线程后，取消就立即返回。

**改变判断的事实：** 线程可能继续提交；重试复用较早对象，当前输入推算身份不一定是实际写入身份。

**选择与原因：** 需要交接时等待事务结果，用实际返回对象及原条件更新处理取消；已完成或被新领取者推进的对象不能由旧请求覆盖。因果验证控制写锁、取消与事务完成顺序。

**重议条件：** 同协程同步完成、事务短且无独立执行者时可能无需交接。按实际执行系统取消合同判断，不假定任务一定可强杀。

## C11 长任务恢复与顾问意见

**情境与假设：** 压缩后早期“实施节奏待决定”留存，后来“一次完成”丢失；顾问部分判断基于旧实现。

**改变判断的事实：** 目标、最新差异和部分留存决定仍可查，恢复未有效利用；重审既发现遗漏也重复上抛已定事项。顾问曾建议已有数据库机制，也曾补出遗漏写方。

**选择与原因：** 续做恢复已定决定与未完工作，审查剩余负担；咨询给必要事实和具体问题，再核当前实现。来源有助纠正，意见不能当事实。

**重议条件：** 新证据推翻前提或用户重新打开决定时重议；只是问验证时说明记录与范围，不自动重跑。

## C12 锁内重复扫描与遗漏写方

**情境与假设：** 变更操作对同一发行目录重复核验，后续只需已有身份，认为每层重扫更安全。

**改变判断的事实：** 起初漏查事故修复写方；补查确认安装、回滚、修复守同锁顺序，本次范围无其他写方插入。

**选择与原因：** 共用原变更锁入口，范围内复用首次观察；自身修改后必要回读、指针切换、恢复日志、补偿由原操作承担。多次扫描没有新事实，锁规则少一份同步义务。

**重议条件：** 离线工具不守锁、旧进程仍改历史树、释放锁后再用结果破坏稳定依据。未知写方须保留未知；“已验证”标记或永久缓存不解决它。

## C13 相同阈值是否同规则（说明性构造）

**情境：** 两个入口都限制同一数量。如果执行同一账户配额政策，一处变更要求另一处一致，共享政策减少同步错误；格式解析仍可各有边界。

**条件翻转：** 一个来自设备承载、另一个来自独立订购政策时，数字相同只是巧合。可共享整数解析，合并业务规则会让独立变化牵连；关联开关可能让调用者理解整套规则。

**推导用途：** 先解释知识为何一致或独立，再定共享层。同负责人、同文件、近期共改不能证明同源。依据[官方 DRY 章节](https://media.pragprog.com/titles/tpp20/dry.pdf)构造，非项目实测。

## C14 进程全局装配覆盖不了其他实例

**情境与假设：** 启动安装全局会话工厂，认为消费者都已装配；两个短会话读取测试通过。

**改变判断的事实：** 请求查询仍取另一全局工厂；另一进程不会取得启动进程对象，同进程两个实例也可需要不同存储。测试只覆盖短会话路径。

**选择与原因：** 消费者取得实际实例启动时传入工厂，保留会话开闭和事务含义。不同实例同时查询及进程启动路径核范围，不把局部测试外推全部装配。

**重议条件：** 稳定进程单例、消费者寿命匹配时全局可以合理存在。不为此例引入容器或禁所有单例。

## C15 恢复结构由三份状态和多份收件清单决定

**情境与假设：** 流程依靠实例属性、大状态袋和手写checkpoint字段表恢复；接续时还逐类补回提前收到的输入。把字段表固定下来似乎消除了反射。

**改变判断的事实：** 新增诊断仍须判断是否进checkpoint，新增Signal仍须同步恢复合并；同轮重试和新Trial清理时点不同。固定表只是又一份需要同步的内部表示。

**选择与原因：** 运行位置、阶段现场和未消费输入分别表达为业务状态；启动/继续共用接收、合并、消费规则，接续直接从这些状态产生。持久候选和实验用稳定引用或小快照，执行句柄/缓存不进恢复。新增内部诊断不改变合同，新增输入只需修改其真实接收主人。

**重议条件：** 旧恢复生产者需按其真实范围解码；小快照与引用按额外查询和故障窗口取舍。阶段拆分不能创建第二路由，也不清掉仍可回到的现场。

## C16 接收完整结果和采用当前业务结果混在两处

**情境与假设：** 完成HTTP Router和业务consumer都解释版本、Skill归因和输出；consumer只要见completed就可跳过重复校验。

**改变判断的事实：** 各封套在两处核验并不相同，旧completed可能未核安装归属，某角色实际派动态schema。只挪validator或信状态标签会漏准入。

**选择与原因：** 公共完成用例按原Job/claim/冻结合同核结果、产物、trace与持久receipt；业务阶段负责当前适用和采用。先让完成完整承重，再删除consumer重复部分。共享公共结果归共同接口，不从某厂商私有实现取类型。

**重议条件：** 历史已接收结果须按当时合同解释；当前资格仍可变化。新增validated标志、第二份结果表不能补缺失入口证据。

## C17 普通查询顺便重建全部历史完整性

**情境与假设：** 每次读记录都加载整条修订/回执、算摘要，认为这样查询最可信；同一响应又在列表和详情多次解析。

**改变判断的事实：** 写侧已有同事务及数据库一致性保护；目标业务只需要选定修订或几项审批事实。普通读取承担了历史诊断和别的record坏行，影响范围与实际用法无关。

**选择与原因：** 普通读查询所需事实，写侧建立一致性，历史诊断/修复有明确入口。一次响应复用解析及空结果，关系事实用同观察语义获取；专属业务不让所有非该类列表都读它。

**重议条件：** 不受约束的外部写方或明确读时全历史验证合同会改变选择。写前锁定持久合同与准备输入的比较仍是新边界，不能连同内部自比较删除。

## C18 迁移拆函数后旧库仍按错误顺序执行

**情境与假设：** 当前metadata先建表，后面重复一份缺表DDL；迁移按函数名字排列。新库和重入绿似乎足够。

**改变判断的事实：** 一个后端已补全缺表，另一个只补子集；真实旧表尚缺某列，先建依赖索引失败。等价约束改名又被当成不合法，实际弱候选键反而需补保护。

**选择与原因：** 升级族拥有旧起点/目标/数据/顺序，总入口按依赖编排，保留原事务。删确定死DDL而保留旧数据和另一后端用途；按约束语义核唯一、非空、生效、立即引用。测试调用真正升级，从fresh/部分旧/完整旧/中途失败/重入观察结构与行为。

**重议条件：** 仅目录等价不证明claim和冻结写保护；最小旧表原语fixture不应迫正式升级加缺列就跳过。后端事务差异不能用统一框架抹平。

## C19 新模块进了源码，安装包和真实环境没跟上

**情境与假设：** 从宿主大脚本抽出安装owner，源码import和摘要通过，因此重排可交付。

**改变判断的事实：** 导出/Docker输入可能漏新模块；实际Runtime镜像缺进程读取工具，退出子进程不被PID1回收。源摘要无法证明包里足够运行。

**选择与原因：** 导出、包数据、Docker和activation消费同步到真实owner；用安装后的解释器跑入口，缺模块负例在切current前拒绝。镜像声明工具、装配回收子进程，保留原清理规则。源码和实际安装消费者共同闭合。

**重议条件：** 目标架构、已发行安装材料和历史恢复分别举证。source通过或另一平台focused不扩成正式artifact验收；开发默认与正式部署范围分开。

## C20 历史解释提取后夺走效果或文件句柄

**情境与假设：** 把历史记录解析、audit、unlink和signal放一个“验证”helper，还预加载待处理文件。

**改变判断的事实：** caller已用ExitStack保持FD；有的待处理项只是路径，逐条才开文件。预加载改变寿命，历史reader若写效果会让恢复owner失去完整次序。

**选择与原因：** 历史解释返回facts/witness；原操作拥有权限、审计、竞争后拒绝、删除/信号和补偿。沿实际文件形态保留caller句柄寿命，当前版本许可与原版本解析分开。

**重议条件：** 存在旧进程写历史树时不缓存；全部写方同锁才复用。不能根据顾问的句柄或锁假设自动增快照框架。

## C21 同一内容算法重复实现，却有不同身份合同

**情境与假设：** Server和native Runtime分别算树摘要，普通包互验一致；合成一个所有摘要通用函数似乎能去重。

**改变判断的事实：** 同时包含同名前缀文件和目录的合法包，两个排序不同而误报漂移；登记摘要包含逻辑清单，安装摘要只含文件。旧交互receipt的幂等摘要还绑定原回传payload。

**选择与原因：** 算法自己排序/编码，安全读取归读取方；Server内部、独立客户端发行内各自共享，跨发行用旧固定向量和实际producer→consumer证明同义。登记/安装身份分开，官方冻结历史发布者不改；旧pending payload原样重送，不重新计算其中摘要。

**重议条件：** 如果内容身份政策确需改变，版本化并迁真实consumer。源码副本数量不能独自决定跨包耦合；让caller先排序或内部再验“已排序”会留下额外协议。

## C22 一次一个动作的面板被设计成复杂响应排序（邻接交互审查）

**情境与假设：** 配置面板刷新后用户立即修改/关闭，晚到响应覆盖确认值；先提议过滤迟到响应。

**改变判断的事实：** 该面板本来一次一个加载/提交，刷新期间禁冲突按钮并保留确认值即可。确需并行的实时搜索/后台刷新页面另判。

**选择与原因：** 简单面板用真实操作互斥；并行页面按对象、请求代次和提交新鲜度接收。处理正常成功后的旧响应及关闭寿命，不把“请求结束”当所有尾巴结束。

**重议条件：** 产品确要在等待中继续消息/查询，就不能全页锁住。规范已有原则，缺的是落实用户动作，不是再写更多字面约束。

## C23 合作替身证明了发信号，却未证明真实进程退出

**情境与假设：** runner测试用安装了signal handler的子进程，断言收到SIGINT，因此转发保护绿；发送SIGTERM后leader退出，也认为任务结束。

**改变判断的事实：** 后台真实pytest继承SIGINT忽略；只终止leader仍留下worker。环境又可能缺系统工具、错candidate目录或模拟架构身份，失败未到目标。

**选择与原因：** runner让测试拥有明确进程组并转发整组；真实pytest/worker证明全部退出。环境按实际制品和目标校正，用未改基线/修环境候选对照，保留失败原因。替身继续用于界面与调用次数，但不扩成OS行为证据。

**重议条件：** 纯函数无需真实进程，真实退出也不证明业务资源停了。局部绿不能替代同候选完整交付，各测试对象和skip单列。
