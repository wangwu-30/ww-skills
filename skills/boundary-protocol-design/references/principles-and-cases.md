# 依据与行为案例

在操作协议方案有争议、怀疑流程过重，或评估本方法的行为收益时读。下面是设计依据与评估题，不要求每次运行全部，也不是已完成的独立模型测试。

## 原则为什么适用，以及适用到哪里

- [Saltzer、Reed、Clark：端到端论证](https://web.mit.edu/saltzer/www/publications/endtoend/endtoend.pdf)：某项应用保证需要端点知识时，中间层确认不能替代它。用来找实际业务结果成立的位置；不从中推出取消TLS、数据库约束或一切中间层检查。
- [RFC 9110 §9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)：重试是否安全取决于动作语义。无响应不是原动作未应用的证明，非幂等重试需要额外依据。
- [AWS：幂等API](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)：同参数不一定是重复意图，调用者表达操作身份更可靠；身份记录和效果需有适当原子关系，保留时长依真实资源与迟到义务判断。借用已存在协议，不强制所有动作加token。
- [Lamport：事件的时间与顺序](https://lamport.azurewebsites.net/pubs/time-clocks.pdf)：因果顺序由实际事件关系建立。单靠时间戳大小不能代替当前尝试、并发赢家和采用条件；这不是要求项目安装逻辑时钟。
- [Python Future.cancel](https://docs.python.org/3.12/library/concurrent.futures.html#concurrent.futures.Future.cancel)与[TaskGroup](https://docs.python.org/3.12/library/asyncio-task.html#task-groups)：运行中的线程不能靠取消Future停止；协程组有自己的等待和取消语义。移到线程后要处理实际完成结果，不能仅根据 await 已取消释放正在使用的资源。
- [Rust ownership](https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html)：资源归属与作用域提供明确收尾规则。用于审查生命周期，不要求换语言；作用域结束也不能证明远端资源已停。
- [Saltzer、Schroeder：信息保护原则](https://web.mit.edu/saltzer/www/publications/protection/Basic.html)：小而清楚的机制与完整授权路径同样重要。真实主体授权和动态撤销仍由原边界承担；身份或内容正确不等于业务动作已获准。
- [Leveson、Thomas：STPA Handbook](https://psas.scripts.mit.edu/home/get_file.php?name=STPA_handbook.pdf)：控制与反馈关系错误、时机错误也能造成损失，即使单个部件没有坏。用来检查结果采用、迟到和过早释放；普通软件任务不因此启动完整安全认证流程。

这些来源支持设计推理，不证明某个新实现已正确。理论假设与项目实际合同不一致时，以已核实的目标和真实义务约束方案。

## 有区分力的行为案例

评估时给旧代码或完整事实与当时任务，不提前告诉模型错误机制；比较有无该Skill或前一版本的实际输出。检查是否找到了正确主人、是否误增协议，以及代价；仅在两组都答对的题上通过，不证明增益。

| 任务事实 | 应有设计 | 应拒绝的处理 |
|---|---|---|
| async入口直接同步下载、SQL与发布；鉴权读事务可能跨发布等待 | 找完整同步动作和鉴权/业务资源的各自寿命，保留发布恢复与写权限 | 只把最后一次HTTP套to_thread；跨线程借用请求Session；去掉写权限 |
| 已提交STARTING，之后再读取ORM并等远端启动 | 保留原读取时刻，投影全部所需事实并结束自有读事务；网络后按原生命周期条件写回 | 为了省连接提前提交父命令；远端已启动后重新要求今天所有准入条件 |
| SQL已读到决策，正常通知随后重投 | 在真实决策读取/采用的对应点消费该输入，保留重投与恢复合同 | 收到信号就丢弃；删除Outbox重试；另造全局去重框架 |
| 第二次执行失败，失败适配只返回基础ID | 实际返回身份穿过错误、诊断与恢复；创建前失败按原缺失语义处理 | 成功路径保留attempt，失败路径猜ID；为所有错误先创建Job |
| 结果/缓存落盘，进程重启后能回传但完成后仍残留 | 找重启读者、匹配回执和真实停止条件，由已有主人处理允许删除的材料 | 只在本次finally删；扫全部旧目录；回执后仍有人使用就删 |
| 相同参数允许创建两个对象，第一次调用无响应 | 沿既有操作身份和查询/幂等合同恢复；不能推断失败 | 内容hash当操作ID；超时直接换ID再建 |
| 上传、安装、激活分别完成，但旧进程仍运行 | 判断当前消费者实际使用哪份程序；保留必要制品身份与激活语义 | 上传成功就宣称生效；hash全部工作文件证明业务正确 |
| 纯函数修一个计算条件、普通改名或仅移文件 | 不触发；误触发时直接回到实际任务 | 创建协议表、事务状态、token、hash或审批问题 |
| 正式合同和当前调用已明确操作结果、恢复责任与资源生命周期，用户只问状态 | 引用当前证据直接回答 | 从头审计、重搭环境、再次设计协议 |
| 所有真实写方在同一独占锁内，观察期间无外部可变来源 | 不虚构并发改写窗口 | 每个helper再扫描或计算摘要 |

评估优先用真实失败前的材料，且分清协议识别、方案正确性、实际实施和集成验收。独立模型对照未做时明确说未做；不把人工走查、格式合法或咨询师同意称为效果证明。若不比已有方法改善相关决策，收回新增入口并合回原方法，不保留一份只增加维护的副本。
