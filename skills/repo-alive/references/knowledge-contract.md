# Repo Alive 知识契约

仅在建立或刷新 `.repo-alive/` 时读取本文件。查询模式无需加载全部模板。

## `overview.md`

保持为导航页，而不是百科全书。至少包含：

1. **目的**：主要用户、输入、核心产出或副作用。
2. **主线**：一到三个最重要的业务/使用流程。
3. **能力地图**：能力域、责任、权威状态/数据、入口和对应主题文件。
4. **技术与进程边界**：语言、框架、存储、异步机制、部署/进程单元；明确基础设施与业务主线的关系。
5. **运行时变体**：改变关键路径的配置、feature flag、Provider、环境或兼容模式。
6. **事实边界**：已验证、仅推断和未知项；区分当前、兼容、规划/休眠实现。
7. **导航**：链接到 `routes.md` 和主题节点。

不要复制每个主题文件的细节。小仓库可以只用 `overview.md` 和 `routes.md`。

## `routes.md`

把入口覆盖与链路深度写成可审计账本。使用最适合仓库的入口单位：单个入口、路由组、CLI 命令组、事件族、公开 API 面或插件扩展点。至少记录：

| 字段 | 含义 |
|---|---|
| Action / surface | 用户或系统动作及入口类型 |
| Entry anchor | 路由、命令、事件、公开符号或清单 target + 文件 |
| Canonical path | 已验证的 handler / application / domain / side-effect 路径 |
| Owner | 对应能力域或主题节点 |
| Trace status | `traced`、`enumerated`、`on-demand`、`unknown` |
| Evidence | 真实符号、配置、测试或搜索证据 |

状态定义：

- `traced`：从入口追到当前问题所需的可观察终点，并核对关键分支。
- `enumerated`：确认入口存在和归属，但没有展开完整链路。
- `on-demand`：本轮有意留待具体问题时追踪，并写明原因。
- `unknown`：入口或终点无法从现有证据确定。

文件末尾必须有覆盖摘要：

- 使用过的发现命令或注册源；
- 纳入和排除的目录/生成物/外部系统；
- 各状态数量；
- 本轮为何选择这些 `traced` 链路；
- 若声称“全部”，证明枚举集合闭合的依据。

## 主题文件

每个 `domains/<slug>.md` 或其他主题节点只展开一个能力，建议包含：

- 责任与边界；
- 用户/系统命令或用例；
- 关键实体及状态权威；
- 已验证的主链和失败/补偿路径；
- 依赖与跨域关系；
- 配置和运行时变体；
- 稳定锚点；
- `inferred` / `unknown` 项及验证办法。

关系较少时直接放在主题文件中；只有跨三个以上主题且能显著改善导航时再创建 `relations.md`。

## 写作与证据规则

- 用相对仓库路径，不写分析机器上的绝对路径。
- 持久主键不用行号；使用真实符号、路由、配置键、target 或标题。
- 不粘贴大段源码、秘密、Token、用户数据、Prompt 或工具输出。
- 不把目录结构、测试通过、Schema 存在或文档声明单独当作运行时接线证明。
- 不用任意小数表达置信度；使用 `verified`、`inferred`、`unknown`。
- 内容唯一，多处只链接；主题文件直接由 `overview.md` 引用，避免深层引用链。

## 盖章前检查

- [ ] `overview.md` 的主线、能力地图、变体和未知项都有当前证据。
- [ ] `routes.md` 同时记录入口发现范围和链路追踪深度。
- [ ] 用户当前问题和代表性高风险路径已经 `traced`。
- [ ] 负面/穷尽性断言带搜索范围与限制。
- [ ] 主题之间无明显矛盾，规划/兼容/当前路径未混淆。
- [ ] 所有链接和清单路径存在，且位于 `.repo-alive/` 内。
- [ ] 未写入绝对路径、秘密、易漂移的主键或无依据的精确度。
- [ ] `stamp` 在所有写入完成后执行，随后 `verify` 成功。
