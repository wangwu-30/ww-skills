# 从需要的结果反推负担

从下一步需要的结果，反推最小交付和必要机制。已知事实由其权威维护，新增事实由执行者交付，
采用规则由下一动作的责任方承担。系统内部需要完整记录，不等于调用者必须生成整份记录。

“最小”按各方完成目标的总成本判断，包括建立和维护共同理解、生成与传递信息、查找与解释、
核验与采用、纠错与返工；不以字段数或文本长度代替。不要求消费者还原与其职责无关的内部过程；
上下文确实共有且仍适用时交付新增信息，消费者欠缺影响行动的知识时补足必要上下文、条件或例子。
必要信息只给引用时，须考虑消费者能否可靠取得和解释。恢复、历史消费和审计有实际义务时，
为其保留所需信息，不因当前成功路径用不到就删除；记录由能可靠取得事实的现有责任方承担。

## 交付只承载需要的信息

沿本次相关入口找到真实消费者及其下一动作，区分程序已知上下文、执行产生的新事实和过程说明。
程序能从可信上下文可靠关联的身份、版本和来源，不让人或 Agent 抄回再逐项自证；
真实产物身份、观测值、未知结果及影响采用的限制才需要交接。自报步骤或文件列表不能替代实际执行证据。

结构化字段须帮助消费者决定、执行或提供确有需要的查询与展示。仅用于复刻过程、且已有正文或 trace
足以承载的说明，不设为必填合同；不能因为已有 schema、存储列或测试，就默认这些字段有必要。
通用 Job 接收负责 schema、合法 claim 和交付幂等；业务消费者负责采用，外部事实按真实对象核验。

## 机制只保护真实行为

对字段、校验、锁、状态、版本门槛、恢复分支及工具包装，说明去掉后会发生哪个当前可到达的错误，
由谁负责防住。没有独立作用就删除或收窄，同时退出专用断言、说明和调用；不先搬层、加兼容或补恢复。
职责归属也不要求新增一层、票据或框架，现有能力能承担就直接使用。

稳定事实由权威解释，不让各层反复比较副本。会变化的授权、claim、并发状态和未知外部效果，
在负责动作的边界守住。保留执行历史不等于锁死当前需求；记录工具版本不等于精确版本准入；
命令与报告的顺序不等于实际效果。失败后修复、额外诊断和合法更新不能仅因偏离原写法而被拒绝。
已有检查失效时，同时审视被检查的交付和流程是否必要，不止修最近一次报错。

## 以实际减负验收

核对调用者实际少填什么、少记什么、哪项机制已退出。复用真实 producer → 接收 → consumer 路径，
证明合法交付能完成和采用，并保留直接相关的非法、越权与并发反例。已发布合同、在途工作和历史消费
按真实义务处理，不静默破坏，也不自动永久保留旧设计；本地修复不冒称已部署或旧失败对象已恢复。

本 Skill 是取舍依据，不增加固定清单、检查器、台账或审阅轮次，不扩大本次授权范围。
