# 共用指标发现与查询知识

本指南为创建和分析入口提供查询知识。创建时遵循调用入口提供的合同，执行 Job 时遵循本 Job 的不可变输入、输入说明和输出 schema；确认与交互沿用各入口规则。本指南不另行定义这些合同。使用已安装的 bytedcli Skill、Provider 说明和当前 CLI 帮助，选择官方只读发现、查询与诊断方式。示例只是有用入口，不是白名单、必经顺序、调用次数或重试预算。

## 从业务含义和现有线索开始

保留用户原始指标含义、来源 URL、参考实验、业务路径/名称、站点/区域和显式范围。URL 可能标识报告、模板、看板或服务，但不一定包含完整指标身份。检查对应对象及其内容；不要把发现简化成搜索看板标题。标题未命中、没有数值 ID 或尚未尝试查找，都不能证明指标不存在或有歧义。元数据检索成功但零候选，只能说明实际检索范围内未找到匹配；身份仍未解析，不能称为歧义，也不能在值查询前报告观测缺失。

结合相关应用/实验元数据、模板类别、报告定义、看板组与指标、描述、公式及筛选定义来缩小候选。保留从原始线索连接到所选指标的元数据路径。名称相似、标题翻译或孤立 ID 都不足以匹配。若两个真实定义仍无法区分，则属于歧义；说明差异并遵循调用入口的交互规则。

把五个问题分开：指标含义是什么（公式、单位、归因、人群）；数据如何生成（新鲜度、覆盖、回填）；指标在哪里展示；哪个官方查询/计算可以读取；结果能支持什么（数值、完整性、比较、统计）。`realtime`、`near-realtime`、`offline` 等业务标签描述数据新鲜度，不一定决定查询 namespace。广告报告即使准实时，也不一定属于用户实时看板 API。沿原业务路径和定义发现，不因新鲜度就选查询面。

## 弄清数值含义

用户规则依赖绝对数值时，检查所选指标定义与数据字段血缘中的币种、单位及原值/展示值倍率。只有适用于该精确定义和范围的现有知识才可复用。另一个指标的 USD 字段、GMV 名称或返回值大小都不能证明这些事实。公式未写明乘数，不能证明输入或返回值无需换算。

区分固定事实缺失、运行后派生值尚未产生和观测值缺失。创建入口先查权威来源，必要站点、范围、指标含义与身份、单位及比较口径仍不明确时，在确认前提出具体缺口；一般性风险接受不能代替选择。未来 ID 或数值不要求预知，但来源及派生规则必须明确。自然语言不是把必要固定事实留到运行时猜测的许可。分析入口按结果合同保留缺口和证据。Analyzer 针对用户独知事实提出非阻塞问题，答复只补充解释；改变当前意图应走正式修改及影响预览。它不能编造换算或擅改本 Job 的冻结身份。已有开放问题不重复提出。工具失败、遗漏日期及可查明事实属于诊断任务，不得转问用户。

指标只对 treatment 有定义时，创建侧按调用入口合同记录适用范围，解释为何 control 没有定义，并在确认界面展示该范围。分析期间，control 查询失败不能成为更改适用范围的理由。只查询和报告冻结的适用组，并始终使用当前 Trial 的版本 ID。

## 确认你找到的对象

| 查询面 | 对象层级 | 观测锚点 |
|---|---|---|
| Libra metric-group | template/bundle → category → metric-group → metric | site、当前 flight、group、metric、比较组 |
| Libra ad-report | folder/tab → report → config-group → metric | site、当前 flight、report、config-group、metric、范围 |
| Libra realtime | dashboard → realtime-group → metric | site、当前 flight、dashboard、realtime-group、所选 metric、比较组 |
| Metrics-FE/Bosun | service/page → canonical metric/expression → 返回 tag groups | site、region、metric/expression、tags、聚合与窗口 |

template 是发现目录，不是第四种 Libra 值查询 namespace。Dashboard ID、realtime-group ID、普通 metric-group ID 和 ad-report config-group ID 各不相同。metric ID 与 dimension/value ID 必须保留其实际 namespace。一个 metric-group 可出现在多个类别中；类别内容也可能只展示子集。找到某个 group 不代表其中目标 metric 一定存在或有值。

共用观测锚点描述查询，不是新增 wire 字段。由调用入口的输出 schema 决定每项事实写在哪里；不得扩展封闭身份对象去容纳表中的所有列。

## 区分身份和值

新实验尚无数据不构成创建失败；元数据可确认固定身份。创建时明确执行必要事实、条件、例外和允许的降级规则，不能仅保留来源链接。运行后才产生的值按已明确来源/规则派生；分析可以选择调用和解析细节，但不得自行补固定站点或范围，也不重写本 Job 需求。

未解析的 namespace 提示可能来自早前 Agent 推断。检查其来源；遇到相反定义时重新调查，不要无限重复同一路径。保留原需求及显式约束，并在本次尝试中记下变更后的发现方法。此方式不能替换用户精确指定的查询身份。成功复用历史证据时须标明时间和检索范围，并说明本次实际读取了什么。

当前 Analyzer 采纳的解析记忆，可指出最近一次成功或失败尝试，即使它不在最近完整报告窗口内。优先使用成功的方法，但替换为当前 Trial/group/window；若证据变化或方法失败，则重新发现并说明原因。旧读数属于历史证据，不是新观测。coverage 计数区分缩减记忆与完整查询事实；条目被省略不能证明该需求从未检查。依据本 Job 的冻结需求与调度说明选择本轮到期检查项，按其输出 schema 报告建议和证据；共用查询知识不决定下次何时运行。

判断查询结果时，分别说明是否已定位指标、是否取得完整响应，以及要求范围内是否有可用观测。已定位但无值时保留请求与已知原因；真实候选无法区分时保留候选和未决差异；发现或查询失败时保留具体故障。按调用入口的输出说明选择相应表示，不用本指南定义状态枚举。

超时不能证明存在多个指标或数据为空。旧证据有时间和范围限制；旧错误不是今天的身份/可用性事实。合法数值 0 不会自动变成缺值。区分零流量、null、缺少行和比较不完整。不得把缺值填成 0，或据此推断结论。

成功空结果，以及 Provider 明确解释为无数据的错误，可以从查询路由和数据生成两侧排查。筛选值合法不说明当前实验产生过这个值：结合官方定义与当前配置，区分未配置、尚未生效、没有匹配流量、数据未产出和查询范围错误。根据已有证据选择能区分这些原因的读取，而不是穷举接口。

冻结身份用于限定正式观测的含义；只读诊断可以检验这个身份是否适用。已有元数据与查询依据矛盾时，可在现有授权内选择有依据的对照条件，保持对象、组和窗口等可比，说明变化及返回差异。对照值是诊断证据，不是原需求读数。先取得数值不代表已找到正确口径；结论还应与来源、数据路由和范围相互印证。

把已尝试方法、排除的假设、查明的原因和待解决条件留在该需求的解析记忆中。配置错误对应正式修订建议；数据确实未产出则对应具体等待条件。后续复用这些结论，有新依据或条件变化才重做相同诊断，正常刷新仍继续。实际修改沿调用方已有流程处理。

重要解释区分用户事实、直接观测和上下文推断，给出出处及适用范围。推断进入记忆或复盘时保留其未验证性质；新的确认只作用于明确确认的内容。预算可以省略整项并显示覆盖，不能留下身份值而删除其推断说明。失败记忆表示原尝试，不表示外部系统持续处于同一状态。

## 保留实际查询范围

保留所有显式人群/筛选、方向、单位、baseline、窗口、聚合和统计方法。未指定的可选约束继续未指定；实质业务缺口按上述澄清规则处理。剩余自由度内选择适当方法并记录实际选择。CLI 默认值和参考示例不是用户需求。

新确认的 Libra 身份应在 `native_query` 内冻结精确原生 bytedcli 子命令、参数向量，以及所需的结果行选择规则。HPO 将此对象视为有界不透明 JSON，不解析或规范化命令字段。当前 Trial、各组绑定/配置或所请求窗口提供的值都应使用占位符，例如 `{{trial.flight_id}}`、`{{group.version_id}}`、`{{group.version_name}}`、`{{group.config.lsa_ltv_opt_traffic_exptag}}`、`{{window.start_date}}`、`{{window.end_date}}`、`{{window.start}}` 和 `{{window.end}}`。执行时依据当前 Trial 和冻结绑定逐组解析，不能取参考 flight 的值。已知固定业务筛选如 `abtest_bingo=1` 保持字符串筛选值 `1`，不得替换成版本 ID。查已安装 bytedcli Skill 和最新帮助确认参数及形式，并将完整实际命令记入 `query_method`。参见[原生 Libra 身份](libra.md#原生查询身份)。

修改原生参数或业务键值属于冻结查询字节，不代表新增 HPO 字段。不得把旧类型化广告范围或 `build_ad_report_command.py` argv builder 当作新身份合同。该 helper 可继续供原调用方使用。

使用已授权站点和已有身份/网络配置。站点、Provider 数据区域和时区是不同概念。官方元数据决定当前实验的版本 ID；名称和参考实验 ID 不能提供当前组身份。记录哪个组为 baseline，以及相对差异方向。不能仅因筛选值与版本 ID 都是数字，就把筛选解释为版本 ID。

参考数值可用于理解匹配范围下的身份，但不能替代当前 Trial 测量。跨查询面的比较需要匹配含义、flight、组、窗口和筛选；数值接近不能证明身份，也不授权更改精确冻结的 query type。数据新鲜度不决定查询 namespace、监控计划或统计成熟度。查询知识不设置 Workflow cadence、阈值、成功规则或实验生命周期动作。

## 检查完整性与筛选执行

HTTP/CLI 外层成功不证明观测完整且可用。检查 Provider 内层状态、解析、截断标志、目标指标，以及冻结 `native_query` 规则所选的行和比较键。组查询可能返回很多指标和比较；单指标 flag 或较短窗口不一定缩小响应。所选行和比较键要依据返回 schema/元数据，不能偷懒取“第一行”。

按调用入口现有规则把大响应留在本地文件。读取结构、状态及相关元数据/值。重定向只能保存工具实际输出，不能找回 wrapper 已截断的数据。`--jq` 是本地投影，不是服务端筛选。可使用受支持的分页、缩小范围查询或 body-file/trace 路径，然后在取值前确认完整性。参见[Libra 响应处理](libra.md#大型-realtime-响应)。

保留原始筛选键和值，使用官方受支持的参数及正确调用位置，检查返回对象、范围、窗口和行。展示标签可能不同于后端键；已知忽略或误用参数的问题保留回归。正确官方调用返回有效匹配结果时可以采用，缺少 SQL/scope 本身不要求拒绝。仅在能力接入/变化或具体矛盾时读取执行明细、SQL或做针对性对照，不强制每轮额外探针。差分只证明此次变化影响返回，相同也不自动证明无效；指标已内含筛选时不要求结果必须改变，零值不证明筛选被忽略。

使用经过清理的请求/错误和现有证据路径。不要把完整原始结果、认证状态载荷、cookie、token 或认证 header 写入分析。只读查询指南不会授予写权限，也不会改变身份、Runtime 权限、Task 确认或 Provider 控制权限。
