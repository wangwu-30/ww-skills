## 追加到“确认问题和合同”的规则

只有任务明确要求新问题、避免重复提交或判断现有修复覆盖时，先取得当前仓库的相关已有工作。先用包含 open、closed、merged 项的 PR 清单缩小范围，发现候选后按文件与实际差异核对；不能仅因标题或关键词没有命中就声称未被覆盖。区分同一根因、相关但不覆盖、同名不同问题，并保留去重依据。

若要交付“当前已有 PR 未覆盖”的判断，应核实清单分页与覆盖范围，记录检查时间、相关 PR 链接及读到的版本。无法穷尽时明确范围；不要把“未搜索到”升级成“从未有人发现”。当前主分支与本地版本不同，要核对相关实现是否仍有偏差。普通修复或用户指定复现不因此新增全量 PR 门槛。
